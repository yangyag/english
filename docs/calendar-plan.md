# 달력 중심 학습 개편 계획

## 목표와 범위
달력을 메인으로 두고 공부한 날짜를 표시한다. 하루 제한과 강제 복습을 제거한다. 신규·복습은 10개 묶음(남은 단어가 적으면 그 수)으로 제출한다. 구현, 문서, 로컬 DB 테스트, 정적 생성, 데스크톱·모바일 브라우저 검증까지 수행한다. 커밋·푸시·배포·운영 데이터 변경은 범위 밖이다.

## 화면과 상태
- 달력: 월 이동, 오늘 표시, 날짜 선택, 신규·복습 개수와 단어 목록. 학습량에 따른 색 단계나 연속 학습 목표 없음.
- 학습 시작: 마지막 신규 학습일(오늘 이전)의 미완료 복습 제안과 신규 학습 버튼을 함께 제공한다.
- 카드: 앞면 → 뜻·예문 → 알아요/몰라요 → 묶음 제출 → 완료 및 다음 묶음 선택.
- 복습은 source_date로 대상을 식별한다. 완료한 순위는 서버에서 제외하므로 재접속해도 이어진다. 복습만 한 날은 대상을 바꾸지 않는다. 더 최근 신규 학습일이 생기면 그 날짜가 새로운 대상이다.
- 날짜 경계: 제출 완료일을 KST로 기록한다. 시작 날짜가 지난 미제출 묶음은 갱신을 요청한다. 이미 성공한 요청의 재시도는 날짜가 바뀌어도 성공으로 처리한다.
- 카드 중간 응답은 브라우저에 임시 저장하며, 달력·진도에는 제출 완료 후에만 반영한다.

## API와 저장
- GET /v1/today: 오늘 날짜, 다음 신규 묶음, 복습 원본 날짜·전체 수·완료 수·다음 묶음.
- POST /v1/today/new 및 /review: request_id, 시작 날짜, 복습 source_date, 전체 순위 응답. 신규는 복습 상태와 무관하게 가능하다. /extra는 동일 신규 API의 호환 별칭.
- GET /v1/calendar?month=YYYY-MM: 해당 월 날짜별 신규·복습 수.
- GET /v1/calendar/{date}: 해당 날짜 단어별 결과.
- GET /v1/progress: 누적 고유 신규 단어 수, 전체 단어 수, 학습 날짜 수, 마지막 학습일.
- 기존 모델은 보존하고 study_batch, batch_result를 SQLAlchemy 모델로 추가한다. request_id는 유일하며 같은 ID의 다른 내용은 409. 쓰기는 PostgreSQL 트랜잭션 잠금으로 직렬화한다.
- 기존 word_result는 신규 저장 형식으로 한 번씩 이전한다. 원본 행과 study_state.next_rank는 보존한다. studied_at의 KST 날짜를 사용하고 날짜/응답을 추측해서 생성하지 않는다. 과거 복습의 원본 날짜는 알 수 없으므로 NULL로 남긴다.

## 검증과 완료 조건
- pytest: 자유 신규, 최근 신규일 전체 복습, 복습 건너뛰기·재개·완료, 날짜 경계·월 경계, 기록 없는 방문, 중복/충돌/동시 제출, 남은 단어·빈 DB, 이전 및 반복 이전.
- nuxt generate 및 TypeScript 검사.
- 분리된 로컬 테스트 DB에서 Playwright로 신규 제출 → 달력 표시 → 상세, 선택 복습·이어하기, 월 탐색, 모바일·긴 예문을 검증하고 스크린샷 보관.
- AGENTS.md, README.md, 이전·복구 절차, 검증 결과 기록을 갱신한다.
- 운영 이전은 별도 배포 승인 후 백업 → 서비스 중단 → 새 코드/테이블 생성 및 이전 → 검증 순서. 로컬에서는 합성 데이터로 이전을 검증한다.
